### 프로세스와 스레드의 차이를 설명하세요

- **프로세스**: 독립적 메모리 공간, 자원 격리, IPC로 통신 (파이프, 소켓, 공유 메모리)
- **스레드**: 프로세스 내 실행 단위, 힙 메모리 공유, 스택은 독립
- 컨텍스트 스위칭: 스레드가 프로세스보다 가벼움
- 멀티프로세스 vs 멀티스레드: 안정성 vs 성능/자원 효율
- Node.js: 싱글 스레드 + 이벤트 루프 (Worker Threads로 CPU-bound 처리)

### 데이터베이스 인덱스(Index)란?

테이블의 검색 속도를 높이기 위한 자료구조 (주로 B-Tree, Hash).

- **장점**: SELECT 쿼리 속도 향상
- **단점**: INSERT/UPDATE/DELETE 시 인덱스 업데이트 오버헤드, 저장 공간 사용
- **종류**: 단일 컬럼, 복합(composite), 유니크, 전문(full-text), 부분(partial)
- 복합 인덱스: 왼쪽 프리픽스 규칙 (leftmost prefix)
- `EXPLAIN`으로 쿼리 실행 계획 확인

### 정규화(Normalization)와 비정규화를 설명하세요

- **정규화**: 데이터 중복 제거, 무결성 보장
  - 1NF: 원자값, 2NF: 부분 종속 제거, 3NF: 이행 종속 제거
- **비정규화**: 읽기 성능을 위해 의도적으로 중복 허용
  - JOIN 비용 감소, 읽기 최적화
- 트레이드오프: 정규화는 쓰기 무결성, 비정규화는 읽기 성능
- NoSQL: 애초에 비정규화된 구조로 설계 (문서 DB 등)

### 트랜잭션의 ACID 속성을 설명하세요

1. **Atomicity (원자성)**: 전부 성공 또는 전부 실패
2. **Consistency (일관성)**: 트랜잭션 전후 데이터 무결성 유지
3. **Isolation (격리성)**: 동시 트랜잭션 간 간섭 방지
4. **Durability (지속성)**: 커밋된 데이터는 영구 보존

격리 수준: Read Uncommitted → Read Committed → Repeatable Read → Serializable

### 시간 복잡도(Big-O)를 설명하세요

알고리즘의 입력 크기(n)에 따른 실행 시간 증가율.

- **O(1)**: 상수 시간 (해시 테이블 조회)
- **O(log n)**: 로그 시간 (이진 탐색)
- **O(n)**: 선형 시간 (배열 순회)
- **O(n log n)**: 효율적인 정렬 (머지소트, 퀵소트 평균)
- **O(n²)**: 이중 루프 (버블소트)
- **O(2ⁿ)**: 지수 시간 (피보나치 재귀)
- 공간 복잡도도 함께 고려해야 함

### 스택(Stack)과 큐(Queue)를 비교하세요

- **스택 (LIFO)**: 마지막에 넣은 것을 먼저 꺼냄
  - 활용: 함수 콜 스택, 실행 취소(Undo), 괄호 매칭, DFS
- **큐 (FIFO)**: 먼저 넣은 것을 먼저 꺼냄
  - 활용: 작업 스케줄링, BFS, 메시지 큐
- **우선순위 큐**: 우선순위에 따라 꺼냄 (힙으로 구현)
- **덱 (Deque)**: 양쪽에서 삽입/삭제 가능

### 해시 테이블(Hash Table)의 동작 원리는?

키를 해시 함수로 변환하여 배열 인덱스를 계산, O(1) 평균 접근 시간.

- **해시 충돌 해결**: 체이닝(Chaining, 연결 리스트), 개방 주소법(Open Addressing, 선형/이차 탐사)
- **로드 팩터**: 저장된 요소 수 / 배열 크기 → 일정 비율 초과 시 리사이징
- JavaScript: `Map`, `Object`, `Set` 내부적으로 해시 구조
- 최악의 경우: O(n) (모든 키가 같은 해시값)

### SQL JOIN의 종류를 설명하세요

- **INNER JOIN**: 양쪽 테이블에 매칭되는 행만
- **LEFT JOIN**: 왼쪽 테이블 전체 + 매칭되는 오른쪽 행 (없으면 NULL)
- **RIGHT JOIN**: 오른쪽 테이블 전체 + 매칭되는 왼쪽 행
- **FULL OUTER JOIN**: 양쪽 모두 포함
- **CROSS JOIN**: 카테시안 곱 (모든 조합)
- **SELF JOIN**: 같은 테이블을 자기 자신과 조인

### CAP 정리란 무엇인가요?

분산 시스템에서 동시에 세 가지를 모두 보장할 수 없다는 정리.

- **Consistency (일관성)**: 모든 노드가 같은 데이터
- **Availability (가용성)**: 모든 요청에 응답
- **Partition tolerance (분단 허용)**: 네트워크 분단에도 동작

실제 선택:
- **CP**: MongoDB, Redis — 일관성 우선, 분단 시 일부 불가용
- **AP**: Cassandra, DynamoDB — 가용성 우선, 최종 일관성(eventual consistency)

### Docker와 가상 머신(VM)의 차이는?

- **VM**: 하이퍼바이저 위에 게스트 OS 전체 실행, 무겁지만 강한 격리
- **Docker**: 호스트 OS 커널 공유, 컨테이너 단위 격리, 가볍고 빠른 시작
- 이미지: 레이어 기반, Dockerfile로 정의
- 컨테이너 오케스트레이션: Kubernetes(K8s)로 대규모 관리
- 개발 환경 통일, CI/CD 파이프라인, 마이크로서비스 배포에 활용
